58. Amends 56. The listing command's run is killed and reaped on timeout, detach, quit, SIGHUP and SIGTERM, as 56 says. A client killed with SIGKILL cannot: while a run lasts, the client keeps a record of it in its state folder (`<state>/reeve-listing/<client pid>-<command pid>.json`: the client's pid and start time, the process group the command leads with its pid and start time, the command), removed when the run ends. Every client's reader, when it starts, reads the records there: for each one whose client no longer runs (no process with its pid and start time), it kills the recorded process group if its leader is still the very command the run started (same pid, same start time, still leading its group), then removes the record. A record of a client still running is left alone; a leftover group whose leader has gone is not killed, since nothing then tells it from a later group given the same id. A command that exits while something it started still holds its output (a daemon, a helper, `listing; (sleep 600) &`) is given 100 ms; then its process group is killed and what it printed is read as its listing, instead of the run timing out. On Windows the command runs as a plain process (herdr's suspended start needs its job guard, which the listing reader does not use) and a run that times out has the command alone killed. A daemon that left the group (`setsid`) is out of hall's reach: it is not killed, and it keeps running with its output closed, so 58's "a daemon" holds only for the listing being read, not for the daemon going.
